# 美术素材规格

给 AI 生成的图片定规格用。**先读第 0 节 —— 有一个必须先做的选择,选错了后面全白做。**

代码现状:`src/utils/AssetGenerator.ts` 用 `Phaser.Graphics` 在运行时画出全部精灵。
`src/assets/` 是真实素材的投放目录,**把图丢进去就自动生效,不需要改任何代码**(见第 7 节)。
下面每一张表都是从代码里**反推出来的真实尺寸与命名**,不是建议值。

---

## 0. 先决选择:像素风 还是 平滑风

`src/config/GameConfig.ts` 现在开着:

```ts
pixelArt: true,          // → 纹理 NEAREST 过滤 + canvas CSS image-rendering: pixelated
render: { antialias: false, roundPixels: true },
```

这一组开关**等价于「整个游戏是像素画」**,和 AI 出图默认的风格是冲突的。两条路只能选一条:

| | A. 保持像素风 | B. 改成平滑风(推荐给 AI 素材) |
|---|---|---|
| 素材 | 必须真的是低分辨率像素画 | 任何风格,线性缩放 |
| ChatGPT 能出吗 | 能,但要 prompt 成 "16-bit pixel art sprite",且**必须手工降到目标像素尺寸** | 能,直接可用 |
| 配置改动 | 无 | `pixelArt: false` + `antialias: true`(两行) |
| 现有程序化素材 | 不受影响 | 不受影响(它们都是纯色块,线性过滤看不出差别) |

**建议 B。** 理由:游戏里最小的怪只有 12×13 像素,AI 生成图在这个尺寸下细节全部糊死;
而如果让 AI 出高分辨率再缩小,`pixelArt: true` 的 NEAREST 过滤会把缩小后的图
抽成噪点。B 路线只要改两行,素材端没有任何额外约束。

## 1. 文件格式

| 项 | 要求 |
|---|---|
| 格式 | **PNG,带 alpha 通道**。不要 JPG(没有透明),不要 WebP(Phaser 要额外 loader) |
| 尺寸 | **必须等于下表的像素尺寸,一比一,不要放大** |
| 色彩 | sRGB |
| 透明 | 背景全透明。不要白底、不要棋盘格、不要投影 |
| 命名 | 见第 3 节,一个字符都不能差 |

**尺寸必须一比一的理由**:游戏不缩放素材。视口固定 1280×720,
素材贴图多大就在屏幕上占多大像素,没有任何自动适配。
出 4 倍尺寸不会让画面变清楚,只会让怪变得巨大。

**怪物的图可以是「等宽横排的多帧图」**,宽度是单帧宽 × 帧数。
**但怪物不走动,只显示第 0 帧** —— 横排只是为了兼容已有的多帧素材,
新做的图给单帧也一样能用。详见第 2.1 节。

---

## 2. 构图规则(这几条比尺寸更容易翻车)

1. **主体居中。** 碰撞圆会自动对齐到精灵中心,代码里已经写死
   (`body.setOffset(frame.realWidth/2 - r, ...)`),所以**贴图尺寸可以随便,
   但画面里的主体必须落在贴图正中央**。偏一点点,碰撞和外观就错位。
2. **不要烘焙阴影 / 描边光晕。** 代码会自己叠 `player_glow` 之类的效果,
   素材里再画一层就会脏。
3. **朝向固定,代码不做旋转。** 投射物贴图的**尖端一律朝右(+X)**
   ——`Projectile` 只设 `setRotation(角度)`,0 弧度就是朝右。
   画成朝上的话,所有飞弹会歪 90°。
4. **投射物是「飞行中的一瞬」,不是「发射者」。** 火球术要画火球,不要画王林在结印。
5. **视觉尺寸贴近碰撞直径。** 碰撞直径来自 `EnemyConfig.size`,见下表的 `size` 列。
   画得比碰撞圈大很多,玩家会一直觉得「明明没碰到却挨打了」。

### 2.1 怪物的贴图:单帧或等宽横排

**怪物不旋转。** `EnemyAiSystem` 五处逼近分支写的都是同一句 `e.setFlipX(dx < 0)`,
全项目没有任何一处对怪物调用 `setRotation` / `setAngle`。所以四视图 / 背面 / 朝上一律用不到,
每只怪真正需要的只有「本体 + 水平镜像」两个方向。

**怪物也不走动** —— 行走动画已经去掉了,满屏怪是平移的。所以:

| | |
|---|---|
| 格式 | 一张 PNG。**单帧最省事**;已有素材是等宽横排多帧的话也照样能用 |
| 尺寸 | 单帧:`单帧宽 × 单帧高`。山野妖兽 = **16×17** |
| 帧数 | 只显示第 0 帧,其余帧不参与任何动画 |

`EnemyFrames.ensureEnemyFrames` 按 `贴图实际宽度 ÷ 单帧宽` 反推帧数,
只把多帧图切成 `<键>_f0 / _f1 / …` 这样的帧名,供 `showFirstFrame()` 取第 0 帧:

- 只给**一张单帧图** → 帧数算出是 1 → 不切,直接整张显示(**不会报错**)
- 给 2 帧或 3 帧 → 照切,但只有第 0 帧会被看到

⚠️ **横排图必须切帧才正确。** 没切过帧的横排图会**整张铺出来** —— 2 帧的表就是
**两只怪并排**,而不是一只怪。这是本节最容易踩的坑,因为它的表象和「素材切错了」一模一样。

⚠️ **而且它不会在日志里留痕。** `getFrameNames()` 默认把 `__BASE` 隐藏掉,
所以「切帧失败」和「切帧成功」打印出来的帧名清单长得**完全一样** ——
区别只在屏幕上。只看控制台是查不出来的,只能进游戏看,或者看启动时
`[切帧] 怪物横排素材切出 N 张` 里的 N 对不对得上已接入的横排图数量。

**帧数对不上不报错这件事很重要**:素材是逐步替换的,管线必须能接受半成品。
反过来「必须 2 帧否则启动失败」会让「先做一张试试」根本没法做。

### 2.2 关于帧(已不适用于当前版本)

历史上这里规定过「两帧只动腿,身体不动」,因为当时怪物会播放两帧行走循环。
动画已经去掉,**新做的图不需要再考虑帧间差异**:给单帧、按第 2 节的构图规则画即可。
如果你的图已经是 2 帧横排(比如沿用旧素材),那第 0 帧要画成**站姿的完整一只怪** ——
被切掉的是右边那一半。

## 3. 命名表 —— 键名必须完全一致

代码里用 `setTexture('enemy_' + id)` 这种**字符串拼接**,没有常量、没有校验。
写错一个字母的后果是:**贴图加载成功、代码不报错、屏幕上是一个空白方块**。

### 3.1 怪物

`enemy_<id>` 与 `elite_<id>` **成对**。精英是同形状 + 提亮 + 描金边,
两者的碰撞尺寸与帧数完全相同。**只要 `elite_*` 缺失,精英就是空白方块。**

两个键的单帧宽必须一致 —— 切帧是按 `enemyTextureSize(cfg)` 的 `w` 硬算的,
精英图和普通图的帧宽不同的话,`floor(width / w)` 算出来的帧数就不对。

### 3.2 法术投射物

| 键 | 尺寸 | 属于 | 朝向 |
|---|---|---|---|
| `proj_fireball` | 14×14 | 火球术 | 圆,无所谓 |
| `proj_nine_nether_fire` | 16×16 | 焚天·火海 | 圆 |
| `proj_jimie` | 20×6 | 寂灭指 | **朝右** |
| `proj_huamo` | 96×44 | 化魔指 | **朝右** |
| `proj_zhanluo` | 40×14 | 斩罗决 · 放射剑气 | **朝右** |
| `proj_sword_array` | 10×10 | 剑阵 · 斩罗决 · 环绕飞剑 | 圆 |
| `proj_enemy_shot` | 10×10 | **敌方**弹丸 | 圆 |

`proj_huamo` 的 96×44 是被数值钉死的:化魔指的碰撞宽度是 2.0 格 = 128px,
再乘 `visualScale: 1.55`。画细了「范围 ×5」在画面上就不成立。

⚠️ **`proj_sand` 和 `proj_bolt` 不在这张表里,它们是死键** —— 见 3.4。
`SandWave`(扇形推进)和 `ChainBolt`(雷弧)两种形态是 `Container` + `Graphics`
现场画的,`WeaponSystem` 只有 `fireProjectile` / `fireOrbiter` 会传 `sp.texture`,
`SpellConfig` 里那两行 `texture:` 字段从来没有消费者。

### 3.3 掉落物

| 键 | 尺寸 |
|---|---|
| `player_down` | 16×24 | 主角 · 朝镜头 |
| `player_up` | 16×24 | 主角 · 背影 |
| `player_side` | 16×24 | 主角 · **朝右**,左边靠 `setFlipX` 镜像 |
| `player` | 16×24 | 缺图兜底,三张全缺时才显形 |
| `xp_gem_0` / `xp_gem_1` / `xp_gem_2` / `xp_gem_3` | 6 / 8 / 10 / 12(正方形) |
| `pickup_relic_<id>` | 16×16,12 件各一张 |
| `pickup_chest_wood` / `_jade` / `_gold` | 20×20 |
| `pickup_heal` / `pickup_xp_pill` | 14×14 |
| `fx_hit` | 16×16(爆炸特效,代码里按 `半径*2/16` 缩放) |

遗物的 12 个 id 与配色见 `src/config/RelicConfig.ts`。**配色必须跟 `color` 字段一致** ——
地面上的遗物和面板图标共用一套色,玩家看到一抹紫就知道捡的是散魔铠甲。

### 3.4 面板图标(法术 10 / 遗物 12)

面板左下角那两栏目前画的是**纯色块**(`UIScene.refreshSpells` /
`refreshRelics` 里的 `add.rectangle(cx, y, 40, 26, color)`)。
色块只能告诉玩家「这是火系的」,不能告诉玩家「这是哪门法术」——
十个格子一排全是色块,玩家只能靠下面的名字认。

| 键 | 尺寸 | 张数 | 说明 |
|---|---|---|---|
| `icon_spell_<id>` | **32×32** | 10 | 法术面板图标 |
| `pickup_relic_<id>` | **16×16** | 12 | **复用**:地面掉落物兼面板图标,不另开键 |

**遗物为什么不另开 `icon_relic_<id>`**:它已经有一个键了,而且地面上那一张
必须一眼可辨——在这种尺寸下它只能是粗壮的剪影,而粗壮的剪影放到面板上
只会更好看。两处用同一张图还顺带保证了一件事:**玩家只学一次「这个形状
=这件遗物」**,不会出现地面一个样、面板另一个样。

⚠️ **法术图标不能复用 `proj_*`。** 投射物是「飞行中的一瞬」,而图标要的是
「这门法术是什么」的符号:化魔指的投射物是 96×44 的一道光带,把它塞进
32×32 的格子等于什么都不剩。而且投射物横着、图标要正着,朝向规则相反。
两者是**不同类别的东西**,所以法术是新键,不是投射物改名。

**规格要求**

| | 法术图标 | 遗物图标 |
|---|---|---|
| 尺寸 | 32×32 | 16×16(面板按 2× 绘制) |
| 内容 | **符箓 / 法阵 / 招式印记**,不是实物 | **物件本身**(瓶、甲、剑、袋) |
| 剪影 | 32px 下必须一眼认出是哪门 | 16px 下必须一眼认出是哪件 |
| 配色 | 必须等于 `SpellConfig.color` | 必须等于 `RelicConfig.color` |
| 背景 | 透明(**不要**烘焙底色方块) | 透明 |

**十个法术 id**:`fireball`(火球术) `fenhai`(焚天·火海) `jimie`(寂灭指)
`huamo`(化魔指) `jianzhen`(剑阵) `zhanluo`(斩罗决) `houtu`(厚土术)
`shanbeng`(山崩地裂) `wulei`(五雷正法) `wulei_hong`(五雷轰顶)。

⚠️ **进化形态的图标必须与基础形态剪影不同。** 寂灭指和化魔指同为紫色,
剑阵和斩罗决同为青白,火球术和焚天·火海同为橙红。颜色分不开的时候,
玩家靠的就是剪影 —— 两个剪影一样,进化就等于没有视觉变化。

**降级行为**:图标缺失时继续画现在的色块,所以这是**逐步替换**的 ——
可以先做常用的几件,其余留在色块状态,游戏不会出现空白方块。

### 3.5 ⚠️ 这些键是死代码,不要为它们生成素材

`AssetGenerator` 会生成它们,但**没有任何代码引用**:

`tile_grass_0..5`、`tree`、`rock`、`bush`、`player_glow`、`proj_knife`、
`proj_magic`、`proj_sand`、`proj_bolt`、`coin`、`pickup_stone`

地面是用一张 `Graphics` 现场画的,不走瓦片贴图。`proj_sand`(厚土术)和
`proj_bolt`(五雷正法)则是因为 `cone` / `chain` 两种形态自己用 `Graphics` 画,
`SpellConfig.texture` 根本没有消费者。做了也是白做。

⚠️ **这一组是最阴的死键,因为它们不报错。** 为死键做图会:文件被加载 →
算作「已接入」→ 不进「仍缺」清单 → 调试面板上一切正常 → 但永远不会被画出来。
`AssetLoader.expectedTextureKeys()` 是按文件名清单枚举的,所以**做一张死键的图
会让总账往「已接入」那边挪一格**,看起来像是有进展。

> ⚠️ **例外:`pickup_relic` 和 `pickup_chest` 不是死键。**
> 它们是 `Pickup.pickTexture` 的**兜底** —— 具体的 `pickup_relic_<id>` / `pickup_chest_<品质>`
> 缺失时,地面上的掉落物会退到这两张。所以它们只在「忘了做具体那张」时才会显形。

## 6. ChatGPT 出图的已知坑

1. **透明背景经常失败。** 让它「transparent background」,大概率给你一张白底或浅色底。
   备选:让它出纯色底(推荐亮绿 `#00FF00`),再批量抠掉 —— 比猜白底可靠。
2. **它会自作主张加背景、光效、文字。** prompt 里要明确写
   `no background, no shadow, no text, no border, no watermark`。
3. **它记不住精确像素尺寸。** 不要指望「给我一张 26×26 的图」,大概率给你 1024×1024。
   正确做法:让它出**大图 + 主体居中 + 纯色底**,再自己缩放到目标尺寸。
4. **一致性。** 同一批怪必须一次对话里出,并说
   `same art style, same lighting, same camera angle, plain top-down 3/4 view`。
   分多次生成会得到五套画风,比程序化素材还糟。
5. **慎用「更多细节」。** 16×16 的怪上任何细节都是噪点。prompt 里应该写
   `bold simple silhouette, readable at small size, high contrast`。
6. **直接要单帧。** prompt 里写 `single sprite, one frame only, full body centered`。
   现在怪物不走动,多帧横排只会带来两类新问题:出图工具给不齐宽度,
   以及切帧出错时屏幕上并排出现两只怪。
7. **别让它出「走路动画」这种词。** 它会理解成多张不同角度的图,
   于是给你正/侧/背三视图 —— 而代码只翻转不旋转(见 2.1),两张用不上。
8. ⚠️ **不要写「dark muted palette」。** 我写错过一次,代价是第一批六只里四只直接
   在地图上消失了(实测平均亮度 28–40,朱雀星地面亮度 45)。
   深色 ≠ 好看;在这张图上**中调才是安全的,黑色是死的**。
   每只怪都要写死 `EnemyConfig` 里的 `color` / `bodyColor`,见 A 节的主色对照表。

### 通用 prompt 模板

```
A single game sprite of <主体>, <视角>, centered in frame,
plain solid #00FF00 background, no shadow, no text, no border, no watermark,
bold simple silhouette, readable at small size, high contrast,
<if 一批> same art style, same lighting, same camera angle as the previous sprites
```

### 投射物额外要求

```
horizontal, pointed tip facing RIGHT, motion trail on the left,
a single projectile in mid-flight, not a character, not a caster
```

### 为什么统一用亮绿底而不是透明底

ChatGPT 的「transparent background」经常直接失败(给白底、浅灰底、或者带渐变的底)。
要求透明就要反复重抽,命中率不稳定。亮绿 `#00FF00` 一次成功率高得多,
而且抠图时绿是画面里唯一的高饱和色,**阈值好设** —— 修仙题材里没有绿到那个程度的颜色,
不会误伤主体。用任何灰白底都做不到这一点:白底抠完会带走所有浅色高光。

## 7. 接线方式(已实现)

**把文件丢进 `src/assets/` 就完事。文件名 = 纹理键,没有清单文件,也没有编号。**

`src/utils/AssetLoader.ts` 用 `import.meta.glob` 在构建时枚举 `src/assets` 下所有层级的 png,
键取文件名(去扩展名)。所以:

- `src/assets/enemy_beast.png` → 键 `enemy_beast`
- `src/assets/characters/proj_fireball.png` → 键 `proj_fireball`(**子目录随意,只看文件名**)

`AssetGenerator.makeTexture` 的第一行是 `if (scene.textures.exists(key)) return;`,
所以真实素材占住的位置**不会被程序化图覆盖** —— `AssetGenerator` 一行都不用改。
放进 `public/` 的话每加一张图都要手写一行 `load.image`,少写一个字母就是一次 404,
而 404 只在控制台留一行红字,游戏照跑、贴图照空。

**怎么知道自己漏了**:启动时控制台会打一份缺失清单(按普通怪 / 精英 / 遗物 / 其他分组),
暂停菜单的调试面板上常驻一行「素材 12/78」。拼错文件名(`enemy_beat.png`)在这里立刻可见 ——
因为预期键 `enemy_beast` 会留在缺失列表里。

小于 4KB 的 PNG 会被 Vite 内联进 JS bundle(实测生效),不用管这个。

接完之后逐项确认,任何一项不过就是这张图白做了:

- [ ] 怪物:主体在**贴图正中央**(横排图则是第 0 帧那一格的正中)
- [ ] 怪物:3/4 侧面朝右,且左右不对称(对称的话 `setFlipX` 读不出方向)
- [ ] 投射物:尖端朝右
- [ ] 投射物:配色对得上 `SpellConfig.color`,火系不是紫色
- [ ] `proj_enemy_shot`:和玩家侧弹体一眼能分开
- [ ] 遗物:12 张都在,配色对得上 `RelicConfig.color`,16px 下剪影两两可区分
- [ ] 法术图标:`icon_spell_<id>` 10 张,配色对得上 `SpellConfig.color`
- [ ] 法术图标:**五对同色的进化形态,剪影必须两两不同**(否则并排时分不出)
- [ ] 法术图标:**没有烘焙方形底板**(代码会画色块,自带底会变成双重边框)
- [ ] 宝箱:木/玉/金三档外观可区分(伪宝匣戴的是**金**的那张)

- [ ] 画面里没有空白方块 —— 任何一处空白都是键名拼错

### 怎么判断贴图有没有接对

**看一只怪是不是一只,不是两只。** 横排素材如果没被切帧,屏幕上会出现
**两只怪并排**(第 0 帧和第 1 帧各一只):

1. 宽度不是 `单帧宽 × 帧数` → `floor(width / w)` 算成 1,不切帧,整张横条直接铺上去
2. 宽度对但仍然并排 → 启动日志里 `[切帧] …切出 N 张` 的 N 是 0 或偏小
3. 显示的是右半只而不是左半只 → 帧名约定和 `EnemyFrames.firstFrameName` 对不上
